## 문제
총알이나 타격 이펙트처럼 한 판에 수백 번씩 생성·파괴되는 오브젝트를 매번
`Instantiate`/`Destroy`로 만들면, 메모리 할당과 가비지 컬렉션이 반복돼 프레임
드랍(끊김)이 생긴다. 특히 ELEM-031(펙트로스핑) 같은 화려한 시각 효과나
ELEM-022(지수적 스케일링)로 화면에 수십 개가 동시에 뜨는 장르에서는 치명적이다.

## 구조
- 기준 형식: 게임 시작 시 필요한 오브젝트를 일정 개수 미리 생성해 비활성 상태로
  쌓아두고(Pool), 필요할 때 꺼내 활성화하고, 다 쓰면 파괴하지 않고 다시 비활성화해
  풀로 되돌린다 [출처: Unity 공식 매뉴얼 "Object pooling", 2026 기준 Unity 6 버전].
- 소비 주체: 총알, 적, 파티클, UI 팝업 텍스트처럼 "자주, 짧게, 대량으로" 나타나는
  모든 오브젝트.

## 핵심 규칙
- 풀 크기는 예상 최대 동시 활성 개수보다 여유 있게 잡는다 - 부족하면 런타임에
  추가 생성이 발생해 최적화 효과가 사라진다.
- 재사용 전 오브젝트 상태(위치, 체력, 애니메이션)를 반드시 초기화한다 - 이전
  사용 흔적이 남으면 버그의 원인이 된다.
- 풀링 대상 오브젝트에 `OnEnable`/`OnDisable`을 초기화·정리 지점으로 활용한다
  (`Awake`/`OnDestroy`는 재사용 시 호출되지 않으므로 부적합).

## Unity 구현 절차
1. 풀링할 프리팹별로 매니저(또는 컴포넌트)를 하나 둔다.
2. 시작 시 지정 개수만큼 `Instantiate` 후 `SetActive(false)`로 대기시킨다.
3. 요청 시 비활성 오브젝트를 찾아 위치·상태 초기화 후 `SetActive(true)`.
4. 수명이 끝나면 `Destroy` 대신 `SetActive(false)`로 되돌린다.
5. Unity 2021+ 환경이면 엔진 내장 `UnityEngine.Pool.ObjectPool<T>` API를 우선
   검토한다 - 직접 구현보다 검증된 관리 로직을 제공한다 [출처: Unity 공식 문서,
   Unity 6 기준].

## 안티패턴
- 매 프레임 `Instantiate`/`Destroy` 반복: 가비지 컬렉션 스파이크로 프레임 드랍 유발.
- 풀 크기를 무한정 늘려 메모리로 해결: 결국 다른 방식의 낭비로 옮겨감.
- `Awake`에서만 초기화하고 재사용 시 상태를 안 씻어냄: 이전 총알의 방향·데미지가
  남아있는 버그.

## 검증 방법
- 성능 검사: 화면에 오브젝트 100개 이상 동시 활성 시 프레임레이트가 목표치
  이하로 떨어지지 않아야 한다.
- 메모리 검사: 장시간 플레이 후 Unity Profiler에서 GC Alloc 스파이크가 오브젝트
  생성/파괴 시점과 일치하지 않아야 한다.
- 콘솔 청결: 풀 부족으로 인한 경고 로그가 정상 플레이 중 발생하지 않아야 한다.

## 조합 궁합
- ELEM-031 (펙트로스핑 그래픽 효과): 파티클·이펙트 폭증의 성능 전제 조건.
- ELEM-022 (지수적 점수 스케일링): 화면의 오브젝트 수가 기하급수적으로 늘어나는
  장르에서 필수적인 최적화.
